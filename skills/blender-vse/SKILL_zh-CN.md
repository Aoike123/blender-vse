# Blender VSE Skill 中文说明

[English version](SKILL.md)

当明确指定的 `.blend` 视频序列编辑器项目是事实源或必要的可编辑交付物时，请使用
本 Skill。它通过四个有界、带修订保护的本地 MCP 工具，安全地检查、编辑、继续制作和渲染
时间线，附加外部生成的代理，并验证持久化，同时保护人工修改。生成源素材时可搭配创作
Skill。如果需要从创意到成片的全流程自动化，请在可用时与导演或制作编排 Skill 搭配：
上层 Skill 负责创意规划、分镜和源素材，本 Skill 负责具备修订保护的 Blender VSE 时间线
执行、渲染与持久化验证。不要将它用于通用视频创作、代理编码、一次性 FFmpeg 任务、
Blender 3D 工作或任意 `bpy` 操作。

将明确指定的 `.blend` 文件视为可编辑的事实源。只能使用 `blender_read`、`blender_patch`、
`blender_acknowledge` 和 `blender_verify`，绝不能改用原始 `bpy`、由 Shell 驱动的 Blender
脚本或隐藏的无头编辑器。

## 建立边界

- 工程保存在工作文件夹的 `blender-vse-projects/` 中。工程路径使用相对于它的写法，例如
  `demo.blend`；引用的媒体也放在其中。
- 要求显式 `.blend` 路径，不扫描文件系统寻找项目。
- 四个工具不可用时停止，并说明本地 MCP 服务尚未安装。不得用任意 Python 模仿。
- `project_not_allowed` 表示路径越出了工程文件夹，不得通过移动或复制项目来规避。
- 代理编码与重建由外部流程完成。`attach_proxy` 只验证并附加已经生成的清单；附加操作不会
  改变源媒体，最终渲染仍使用原始媒体。
- 只有用户明确要求创建该项目时，才能设置 `create_if_missing=true`。检查和续作绝不能
  隐式创建缺失文件。

## 选择工作流

- 全流程自动化任务应由可用的导演或制作编排 Skill 负责创意简报、分镜、素材方案和验收
  标准，再将明确的时间线修改交给本 Skill。本 Skill 只负责对指定 `.blend` 项目进行具备
  修订保护的 Blender VSE 执行与验证。
- 检查、解释或诊断任务只读；除非用户同时要求修改或接纳状态，否则不要执行 Patch 或
  acknowledge。
- 创建或编辑使用下方观察式编辑循环。
- 在暂停、交接、压缩或状态不确定后继续工作时，应假定先前的观察已经过期，并从新的摘要
  读取开始。
- 发生失败时，只有结构化错误指出具体分支后才读取 [recovery_zh-CN.md](references/recovery_zh-CN.md)。

## 观察式编辑循环

1. 使用确切的项目路径和 `view="summary"` 调用 `blender_read`。
2. 只读取任务需要的区域：
   - `range` 需要 `frame_range`，适合读取有界的时间线范围；
   - `detail` 需要片段 ID、通道、片段类型或帧范围，适合在修改已命名片段前使用；
   - 只加入必需 `include` 组：`text`、`source`、`transform`、`audio`、`proxy` 或 `metadata`；
   - `has_more` 为 true 时，使用完全相同的查询参数继续请求 `next_cursor`。
3. 理解观察到的时间线，并形成一个语义连贯的命令批次。构造命令时，请阅读
   [commands_zh-CN.md](references/commands_zh-CN.md)，然后只在
   [command-index.json](references/command-index.json) 中查找所需操作。
4. 对同一个明确指定的项目路径调用 `blender_patch`，并传入最新读取的 `revision`、`timeline_hash`
   和 `observation_id`。为该批次生成一个唯一且稳定的 `patch_id`；只有在重试完全相同的
   批次时才能复用。
5. 再次调用 `blender_read`。绝不能根据 Patch 回执构造第二个 Patch，也不能复用观察 ID。
6. 仅在需要时重复定向读取 -> Patch -> 读取。修改完成后调用 `blender_verify`；如果已知
   预期片段数量，也可以一并提供。

只有用户明确要求旧版兼容或调试，且有界视图无法回答时，才使用 `view="full"`。不得把它作为日常编辑准备。

## 人工修改

将外部改动过的时间线视为用户的工作。在采取任何后续操作之前，必须读取并理解新状态。
如果新状态与请求的工作兼容，可以用 `blender_acknowledge` 接纳该次观察到的状态，然后再次
读取。如果它与用户意图冲突，或正确选择不明确，则停止并询问。绝不能接纳未观察到的状态，
也不能使用 acknowledge 绕过过期 Patch。

## 上下文状态

不断增长的对话上下文属于 Agent 宿主，不属于 MCP 服务。只维护紧凑恢复胶囊：

- 明确的项目路径与当前用户意图；
- 最后确认的修订和时间线哈希；
- 有界的近期 Patch ID、已完成动作、相关稳定片段 ID 和已验证输出；更早的历史只保留总数
  与摘要；
- 未解决的编辑决策和下一次定向读取。

压缩或交接后，不保留观察 ID、游标、完整片段转储、原始日志或窗口诊断。恢复时从摘要
读取开始，并在任何修改前取得新的定向读取结果。

## 完成条件

只有 Patch 后的读取与预期时间线一致，并且 `blender_verify` 确认持久化，时间线变更才算
可靠写入。`blender_verify` 只能证明它所报告的持久化结构事实，包括场景绑定、可见性和
可选的片段计数；它不会检查渲染帧，也不能证明视觉或创意效果正确。对于明确要求视觉效果
的任务，报告完成前必须单独检查：`sample_frame` 命令会返回单帧的数值 RGB 网格（行序自上
而下），其余部分审看预览或成片。报告中应包含项目路径、已应用的编辑、
返回的最终修订和哈希、输出路径，以及所有警告或未决选择。
