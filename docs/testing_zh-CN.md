# 测试

[English version](testing.md)

## 一份计划，九个测试档位

[`tests/test-plan.json`](../tests/test-plan.json) 是规范测试清单。[`tests/run.py`](../tests/run.py) 读取该清单，为各测试套件应用对应的环境策略并强制执行超时，只生成一次合成素材，同时报告耗时。每次 pytest 调用都会使用一个由 Git 忽略的唯一 `.tmp` 根目录，目录名包含测试档位、Python 版本、进程 ID 和时间戳；运行结束后由运行器清理。这样既能避免操作系统临时目录冲突，也能防止矩阵任务、并发运行或不同本地身份复用同一目录。

如果缺少 pytest、JSON Schema 验证器、MCP、uv、coverage、Blender 或 FFmpeg，预检阶段就会失败，不会等到测试档位运行一部分后才报错。

| 档位 | 运行内容 | Blender GUI | 目标 / 硬超时 |
| --- | --- | --- | ---: |
| `fast` | 核心单元与契约测试，不含 MCP SDK 测试 | 否 | 3 / 10 秒 |
| `coverage` | 同一核心测试及分支覆盖率 | 否 | 5 / 15 秒 |
| `mcp` | 安全边界、四工具接口、覆盖率及真实 stdio | 否 | 4 / 10 秒 |
| `plugin` | 精确 `.mcp.json` 命令与四工具发现 | 否 | 60 / 180 秒 |
| `harness` | 真实 Claude 清单验证与插件 MCP 连接 | 否 | 60 / 180 秒 |
| `stateful` | 场景回放及 250 轮上下文/压缩评估 | 否 | 5 / 15 秒 |
| `blender-headless` | 原生媒体检查器 | 否 | 15 / 60 秒 |
| `blender-smoke` | 一条公开 API 工作流 | 是 | 120 / 240 秒 |
| `blender-full` | 冒烟加全部已登记集成脚本 | 是 | 900 / 1200 秒 |

```bash
python tests/run.py list
python tests/run.py fast
python tests/run.py coverage
python tests/run.py mcp
python tests/run.py plugin
python tests/run.py harness
python tests/run.py stateful
python tests/run.py blender-smoke
```

测试脚本默认在第一次失败时停止，以节省时间；需要完整回归报告时可传入 `--keep-going`。使用 `--dry-run` 可以查看实际执行的命令，而不会启动 Blender。

目标耗时是一项性能信号，超出后会被报告为慢；硬超时则是终止卡死进程的安全边界。将二者分开，可以避免正常的 CI 波动导致误报。

无头档位会显式关闭可选的实时一致性检查，因此即使 Bridge 恰好正在运行，也不会把该档位变成 GUI 测试。

插件档位首次运行时可能需要准备本地 uv 环境，因此 60 秒目标包含依赖解析时间。它只列出 MCP 工具，不会打开 Blender 或修改项目。从检出目录启动并预热缓存后，从解压归档启动的过程会被强制设为离线模式。

Harness 档位是明确的发布门槛，不属于拉取请求 CI 任务。它使用固定版本的 Claude Code CLI 严格验证并安装插件，并连接插件的 MCP 服务器。所有客户端状态都隔离在仓库的临时目录中；首次运行可能需要访问 npm，但不会修改用户的 Claude 配置。

运行 GUI 档位的进程必须与 Blender 位于同一交互式桌面。服务、沙盒和隔离桌面即使能够枚举 Blender 窗口，也会正确返回 `gui_not_visible`；不得为了让托管自动化通过而削弱这项检查。

## 快速测试门槛验证的内容

快速测试门槛既不需要 Blender，也不启动子进程，但覆盖范围超过普通单元测试。它与独立的 MCP 门槛共同检查：

- 所有公开操作都能路由且只属于一个功能族；
- 适配器、路由、Schema、只读策略、无头策略、内部原语和已移除操作错误保持同步；
- 修订 API 的成功、回滚、过期基线、检查点与会话失败；
- summary/range/detail 过滤、分页、过期游标、UTF-8 字节截断与硬响应预算；
- 正确发现四个 MCP 工具、自动生成的输入校验、内存协议调用、拒绝越出允许根目录的请求，以及按项目串行执行；
- Skill 命令索引一致性、示例 Schema、严格限定的 MCP 接口、依赖元数据、参考链接与指令和索引的字节上限；
- 插件清单版本/路径完整性、审批策略、环境变量允许列表、确定性市场归档与内置文件允许列表；
- 恢复胶囊 Schema、预算、历史摘要和有状态场景语料的完整性；独立的有状态测试门槛会测量 250 个编辑循环；
- 可移植的跨客户端配置、版本和协议一致性，以及确定性的源码分发包、wheel 和插件归档；
- Bridge 帧结构、分片 Socket 读取、回环策略与项目身份；
- 运行器模式选择、超时、结果解析与临时脚本清理；
- 代理清单哈希、路径包含、必需字段与过期源；
- 所有本地 Markdown 链接、中英文文档配对、包版本、许可证、源码清单以及测试计划/上下文策略条目。

参数化操作目录测试无需启动 140 个 Blender 进程，就能覆盖所有公开操作。渲染和持久化行为仍在 Blender 档位中验证，因为 Mock 无法为这些行为提供有效证据。

## 覆盖率范围

`coverage` 档位测量确定性的宿主侧 Python 行为及其分支覆盖率。固定的 bpy 模板正文、随包提供的 Blender 内部 Bridge，以及平台或 GUI 专用的实时会话状态机，都不计入核心数值阈值。不依赖外部包的 MCP 授权测试仍计入核心覆盖率；可选协议服务器则使用独立档位，并在支持的最低和最高 Python 版本上，对 MCP 包执行更严格的 85% 分支覆盖率阈值。被排除的 Blender 代码仍由针对性的协议与安全契约以及真实 Blender 档位验证。强制使用 Mock 覆盖每段嵌入式脚本和操作系统分支，只会提高覆盖率数字，却降低结果的可信度。阈值与排除项位于 `pyproject.toml` 和 `tests/test-plan.json`。

## 集成安全

- 素材由色块和正弦波过滤器生成，不提交来源不明的媒体文件。
- 项目与渲染只写入被忽略的仓库目录。
- 测试生成的 Blender 脚本与日志使用仓库忽略的 `.tmp`，不使用共享用户状态。
- GUI 档位串行执行，因为同一可见 Blender 会话独占时间线；不得并行。
- 会话守卫拒绝切换离开另一个已打开的人工项目。
- 初始 GUI 验证失败时，冒烟测试只会关闭由自身启动、没有未保存更改的空白项目或对应测试项目；绝不会关闭含有未保存更改的项目或无关项目。
- `BLENDER_VSE_ALLOW_DIRECT_MUTATION=1` 只应用到指定旧测试；公开冒烟流程不使用。
- 运行完整档位前关闭个人 Blender 项目。

## CI 布局

CI 并行运行六个独立任务：

1. 在受支持的最低和最高 Python 版本运行快速测试；
2. 在主 Python 版本运行一次覆盖率；
3. 在受支持的最低和最高 Python 版本运行完整 MCP 契约，并对真实 stdio 子进程执行一次发现测试；
4. 在一个 Python 版本执行与声明完全一致的 uv 插件启动流程；
5. 运行确定性的有状态与压缩场景评估；
6. 构建一次源码分发包、wheel 和插件，并进行归档与 CLI 冒烟检查。

MCP 测试与核心 `fast`、`coverage` 测试收集相互隔离，因此无关任务不会重复导入可选 SDK 或启动 stdio。只构建一次，避免过去在每个 Python 矩阵项中重复构建。Blender 档位仍是明确的发布门槛，因为托管运行器无法提供必需的可见桌面证明。

## 添加测试

- 纯行为测试放入 `tests/unit`。
- 一致性、Schema、文档、打包和测试计划检查放入 `tests/contract`。
- 真实 Blender 行为放入 `tests/integration`，每个新脚本登记到 `blender-full`。
- 只把最小代表性流程加入 `blender-smoke`。
- 将 `fast` 的目标耗时保持在三秒；优先使用参数化和测试替身，避免启动进程。
