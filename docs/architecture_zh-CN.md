# 架构

[English version](architecture.md)

## 边界与事实源

Blender VSE Control 是围绕持久化 `.blend` 时间线构建的本地控制平面。`.blend` 是事实源；渲染媒体、JSON 响应、代理文件和会话观察均为派生产物。

本包在运行时不依赖 Agent 框架、生产数据库、下载器或媒体服务商。

## 在全流程自动化中的职责

Blender VSE Control 有意只承担时间线执行与验证。如果任务覆盖创意方向、分镜、素材生成或
获取以及最终组装，应由可用的导演或制作编排 Skill 负责上层流程：它把创作意图整理成明确
的剪辑方案，再把具体的 VSE 操作交给本项目执行。

这两层由 Agent 宿主组合，Blender VSE Control 不强制依赖某一个导演 Skill。因此，上层可以
更换创作工具或媒体服务，而指定的 `.blend` 仍是具备修订保护、可由人工继续编辑的事实源。

```text
应用 / Agent 宿主
        |
        | read / patch / acknowledge / verify
        v
可选本地 stdio MCP       仅四个工具；显式授权项目根目录
        |
        v
blender_vse.api          协作与检查点策略
        |
        +--> catalog      公开能力与执行清单
        +--> context      有界视图、游标与字节预算
        +--> resume       有界压缩/交接胶囊
        +--> router       公开操作边界
        v
blender_vse.blender      结果封装与保存验证
        |
        +--> vse_ops      固定、类型化的 bpy 脚本模板
        +--> runner       可见会话/无头执行策略
        +--> live_session 本地 Bridge、身份与可见 UI 证明
        +--> .blend       规范的持久化状态
```

## 规范清单

项目避免重复维护同一份列表：

- `catalog.py` 管理操作族、只读操作、无头操作、项目可选操作、控制平面命令、内部原语及已移除操作的迁移错误。
- `context-policy.json` 管理响应预算、可选字段组和压缩/恢复状态。
- JSON Schema 定义序列化输入和输出结构。
- `tests/test-plan.json` 管理测试档位和预算。
- 契约测试验证操作目录、适配器注册表、路由、Schema、CLI 和文档始终保持同步。

## 执行模式

交互编辑要求 Blender GUI 可见，并处于 Video Editing 工作区。执行前，会话层会验证 Bridge 进程、原生窗口、请求的项目、场景绑定、时间线区域、预览区域和可见片段数量。证据缺失或存在歧义时，操作会按失败处理并拒绝执行。

只有原生媒体检查、渲染和新进程持久化验证可以在无头模式下执行。交互编辑绝不会静默回退到另一个后台 Blender 进程。

## 修订协议

1. `read` 返回持久化修订、完整时间线的规范哈希，以及单次使用的观察 ID。
2. `patch` 在修改前立即验证这三项。
3. 命令以一个原子批次执行，并使用幂等 Patch ID。
4. 成功时只提交一个修订；失败时恢复到 Patch 前的状态。
5. 执行下一个 Patch 前必须重新 `read`。

在 Blender 中手动编辑会改变规范哈希。调用方必须读取并理解变化，然后基于新状态继续，或显式接纳该变化。控制器绝不会接纳未经观察的变化。

## Agent 上下文与状态

对话历史由 Agent 宿主保存，不属于本包。上下文层通过 `summary`、`range` 和 `detail` 视图限制工具结果的大小。分页游标绑定到单个时间线修订和查询。Agent 宿主压缩上下文后，调用方应丢弃观察 ID，并重新执行定向读取。见[上下文模型](context-model_zh-CN.md)。

可选 MCP 进程刻意保持轻量：它只保留有界、确定性的项目锁分片，不保留对话消息、观察结果或“当前项目”。每次调用都必须提供项目路径并重新进行授权。见[本地 MCP 服务](mcp_zh-CN.md)。

可选 Skill 提供提示词与编排层。精简入口定义状态转换规则；仅在需要时从专门的参考文件中加载命令签名和故障恢复指南。快速测试门槛会将生成的命令索引与权威操作目录及 Python 签名进行比对。

`resume.py` 是 Agent 宿主侧的辅助函数，并非对话存储。它把需要保留的交接事实整理成 4 KB 胶囊，保留近期历史，并记录总数和摘要。有状态评估语料会在 250 个合成编辑循环中回放冲突与恢复路径，测量活跃上下文的大小，但不会把 Agent 对话归于核心库管理。

## 分发

`install.sh` 与 `install.ps1` 通过 `uv tool` 在 uv 托管的 Python 3.12 上安装 `blender-vse-mcp` 命令，因此系统 Python 不是最终用户依赖。任何 MCP 宿主都只需注册这一条 stdio 命令。仓库根目录同时也是 Codex 与 Claude Code 的市场插件，启动的是同一个服务。工程统一解析到 `<workspace>/blender-vse-projects`，安装过程不记录任何绝对路径。Blender 和 FFmpeg 仍需单独安装。这些本地方案都不声称 stdio 满足公开插件提交所要求的 HTTPS 接口。见[安装](installation_zh-CN.md)。

## 检查点恢复

恢复属于控制平面事务，不是普通的 bpy 操作。控制器会验证已观察基线、创建可恢复备份、关闭对应的 GUI 项目、替换文件、在可见界面中重新打开项目、再次执行会话验证，并完成新修订。它必须是所在 Patch 中的唯一命令。

## 兼容性

为兼容原内嵌实现创建的时间线，内部 `video_ai_*` 自定义属性和 `VP_RESULT` 进程标记会保持稳定。它们属于持久化与传输协议细节，不属于公开的 Python 命名空间。

## 外部集成

代理媒体编码和项目级资产身份由 Agent 宿主应用负责。本包会在附加外部清单前验证代理哈希、源元数据、路径包含关系和配置兼容性。资产操作只把 Agent 宿主拥有的 ID 绑定到片段，不会导入其注册表。

本地 Bridge 威胁模型见[安全策略](../SECURITY_zh-CN.md)，公开/内部边界见[操作目录](operations_zh-CN.md)。
